# TCP MSS/MTU tests

Tests for the behaviour described in [#43](https://github.com/newsnowlabs/docker-ingress-routing-daemon/issues/43): the TCP MSS advertised by DIRD-configured service containers, and whether full-sized segments survive when PMTU discovery does not.

All scripts require root and are intended for a disposable host or VM.

## `lab.sh` / `run-matrix.sh`

`lab.sh` builds a four-namespace lab with no Docker dependency:

```
client  203.0.113.10                      MTU $CLIENT_MTU (default 1500)
   |
lb      203.0.113.1 | 10.0.0.2 (ingress)  ingress_sbox analogue: DNAT without SNAT, TOS 2 towards the ingress subnet
   |                                      (lb side of the client link is MTU 1500, as for an internet path)
srv     eth0 10.0.0.5  (ingress)          MTU $OVERLAY_MTU (default 1450)
        eth1 172.18.0.3 (default route)   MTU 1500 (docker_gwbridge analogue)
   |
gw      172.18.0.1
```

It extracts DIRD's own `log()` and `route_ingress()` functions from the script under test and runs them against the `srv` namespace (with `docker inspect` stubbed), so the container-side rules, sysctls and routes are exactly those DIRD would apply.

The client connects, records its `TCP_MAXSEG` (derived from the MSS advertised in the SYN-ACK), sends 3000 bytes, and reads the server's 4000-byte reply, which reports the bytes received, the accepted socket's fwmark and its own `TCP_MAXSEG`. With `blackhole`, ICMP 'fragmentation needed' generated by `lb` is dropped, simulating a PMTUD black hole.

`run-matrix.sh` runs `lab.sh` against three versions of DIRD (pre-fix, the fix as proposed in #43, and the working tree) across ingress MTUs of 1450, 1500, 1550 and 8950 and client MTUs of 1500 and 9000, and asserts the expected client MSS, bytes received and socket mark:

```sh
sudo tests/mss-mtu/run-matrix.sh [<pre-fix-ref> [<proposal-ref>]]
```

Limitations: the lab does not use IPVS or VXLAN; `lb` performs DNAT and TOS marking in one namespace rather than across the host and `ingress_sbox`; the jumbo-client cases model a silent drop at a 1500-byte hop (veth drops oversized frames without ICMP).

## `ingress-mtu.sh`

Requires a single-node swarm (`docker swarm init`) with the `busybox:1.36` image available. For each `com.docker.network.driver.mtu` value given, it removes and recreates the `ingress` network, starts a test service, and reports the MTUs of the ingress interfaces in the service container, in `ingress_sbox` and in the ingress overlay namespace:

```sh
sudo RESTART_DOCKERD=1 tests/mss-mtu/ingress-mtu.sh default 1450 1500 1550 1600 9000
```

**Warning:** this removes and recreates the swarm's `ingress` network.
